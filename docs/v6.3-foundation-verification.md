## Contracts and resolved details

Call `FactFlightReports.report(sessions, {learnerId})` or `normalize` with a specific learner ID. `learnerId: null` explicitly selects unassigned legacy records. Guest records are excluded from this saved-history adapter; a later temporary-Guest UI adapter remains separate. Duplicate/missing session IDs in the selected history throw rather than mix or double-count records. Other learners are excluded before this check.

`FactFlightReadiness.evaluate(normalizedFlights, scope)` uses an in-memory scope descriptor: `{kind:'level', activity, level}` (zero-based level); `{kind:'families', activity, families:[7], range:10}` (one family for readiness); or `{kind:'school', activity:'multiplication', table:7}`. No descriptor is persisted. Existing selected-table records retain through-10 meaning. Through-12 multiplication and selected division are supported only as explicit pure calculation inputs; tests use in-memory fixtures, not speculative saved records. The saved reader does not accept invented range/schema extensions.

**Owner-approved window correction in this increment:** accuracy/coverage use the latest 60 level encounters or 40 family encounters within the outer 12/8 contributing flights. Completed-flight credits count across that outer window, not only flights retained after the encounter cap. This makes repeated 60-question flights a viable route. Return `completionEvidenceIds` separately from capped `evidenceIds` so explanations can name both populations. Invalid facts/outcomes/dates do not earn completion credits.

Flights sort by date descending, then session ID for deterministic ties. Within a flight, use saved first-submission offsets descending, with item index only as a stable fallback. Skip-only or previously skipped encounters do not have reliable first-encounter timestamps. If the cap cuts through a flight with missing chronology, return `uncertainBoundary` and an unmet valid-evidence requirement; never claim display order proves chronology. No extra timestamps are saved. Unknown/invalid scope facts stay visible in reporting diagnostics; invalid retained evidence cannot award readiness.

The approved Squares Level 3 example takes precedence over raw rounding: tiers of one or two families require all of them. Larger tiers use `min(10, ceil(30% × tier families))`. Thus both 11² and 12² are required, not just one. Every current tier is enumerated in the tests; no coverage requirement is silently removed for an empty tier.

Identity flags: addition zero addend; subtraction subtract-zero/equal operands; multiplication zero/unit factor; division zero dividend/unit divisor/equal operands; bonds a zero known or missing part; doubles/halves zero input; squares zero/unit base. Pool validity still governs: defining a flag never adds a fact to a pool. ×2, ×5 and ×10 are not blanket identities.

Reports preserve raw milliseconds; formatting/rounding belongs to the future UI. Finite non-negative active times, including zero, contribute to averages. Missing times are counted explicitly. A mixed review's activity time is matching question active time, while overall practice time remains recorded session elapsed time; activity session counts overlap. Unknown comparable-setup metadata is counted as uncomparable instead of merged into personal bests. Recent incorrect numeric values are capped at 12; their documented fallback order is not presented as precise recall chronology.

Activity summaries enumerate five levels, and (for multiplication/division) the caller's explicitly supported family ranges, with one separate bar for each range. The default calculation range is through 10 with families 1–10; the later selector integration can explicitly request ranges 10/12 and families 1–12. Timed multiplication includes the nine original School Tests. Activity readiness excludes timed achievements; there is no composite percentage blending ranges or speed.
